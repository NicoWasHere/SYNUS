SYNUS

A livecode node environment. You write a graph of small nodes in one JS-like text file; each node reads other nodes' outputs, does some WebGL2/Canvas2D/ three.js/Hydra work, and publishes its own output. Ctrl+Enter sends the whole file to the running graph. This page documents everything currently built.

Overview

A project file is a real ES module that exports one thing: 

export const nodes = {
  someNode: {
    in: { src: 'otherNode.output' },
    code(inputs, state, t) {
      // ... do something with inputs.src, return an output
      return { screen: someTextureLikeValue };
    },
  },
};

Every node is just { id, code, inputs, state, error, lastOutputs }. There's no such thing as a node "type" — a node is whatever lib class its code() happens to call (GLSL, Canvas2D, an effect, a Pattern, nothing at all). Nodes never call each other directly — they publish to a shared bus keyed by "nodeId.portName" and read from it via their in wiring. That's what makes feedback loops possible (a node can read its own last-published value through a Lag or Delay) and keeps every node decoupled from the others' internals.

Every tick (driven by requestAnimationFrame), the graph:

  1. topologically sorts nodes by their in wiring (cycle-tolerant — a node depending on itself doesn't hang, it just reads last tick's value)
  2. for each node, reads its wired inputs off the bus, calls code(inputs, node.state, t)
  3. publishes whatever it returned onto the bus as "thisNodeId.portName" for each key
  4. if it threw, keeps showing that node's LAST successful output and records the error (shown in the error panel) — one broken node doesn't blank out the whole graph

node.state is a plain object that persists across every patch send for as long as that node's key exists in the file — this is what lets a node build an expensive resource once (a shader program, a Canvas2D, a three.js scene) and reuse it every tick, instead of rebuilding it 60 times a second. See State, useInstances, newPatch for the implications.

Node anatomy & the bus

rainbow1: {
  in: { src: 'square1.screen' },   // portName is whatever the upstream node returned
  code(inputs, state, t) {
    // inputs.src === whatever square1's code() last returned under "screen"
    return { screen: something };  // publishes as "rainbow1.screen"
  },
},

in keys are just { localName: 'upstreamNodeId.portName' }. There's nothing special about the name screen or output — it's a plain string key in whatever object your code() returns, and the node wiring to it has to spell that exact key. A very common beginner mistake is writing in: { src: 'foo.output' } when foo's code() actually returns { screen: x } — that reads as undefined silently (the bus just has no entry for "foo.output"), not an error.

Only render(value) (see below) actually draws to the visible canvas — returning { screen: x } from some node by itself does nothing visible unless another node reads it and eventually calls render() on it (or on something derived from it).

State, useInstances, and newPatch

node.state persists across every successful patch send, for as long as the node's key stays the same. This is deliberate — editing one line in one node shouldn't blow away another node's compiled shader, or reset a running feedback buffer. The mechanism for "build this once, reuse it every tick" is: 

code(inputs, state, t) {
  const use = useInstances(state);
  const glsl = use(GLSL);              // constructed once ever, reused every tick after
  const rotated = use(Rotate).tick(inputs.src, t * 20);
  ...
}

useInstances(state) returns a use(Ctor, ...args) function. Each call constructs new Ctor(...args) the very first time it runs for that call, then just hands back the SAME instance every tick after, keyed by call order — so use() calls must be unconditional and in the same order every tick (never inside an if), the same constraint React hooks have. This works for any class: GLSL, Canvas2D, any effect, Pattern, a class you write yourself.

For a one-time setup that isn't a single class (three.js's scene/camera/mesh, for instance), the plain idiom is: 

if (!state.scene) {
  state.scene = new THREE.Scene();
  ...
}
The gotcha: both of these only ever run their construction ONCE, ever, per node. Editing what's inside a use(Ctor, ...) call's arguments, or inside an if (!state.x) block, and hitting Send again has no visible effect — the code that would apply your edit doesn't run again. This bit three separate things this project ran into directly: changing a three.js node's geometry, changing which Pattern shape a use(Pattern, Pattern.sin(1)) call constructs, and any other "build once" idiom in general.

There are three ways to deal with this, pick whichever fits:

1. The per-node reset button

Click the small ↺ next to the node's line (see Per-node reset button) — clears state to {}, so every if (!state.x) guard fires again on the very next tick. No resend needed.

2. newPatch

if (!state.scene || newPatch) {
  state.scene = new THREE.Scene();
  ...
}

newPatch is a plain global (not a function call) that reads true for exactly one tick — the first tick right after a send succeeds — and false every other tick. Add || newPatch to a one-time-setup guard and it rebuilds automatically on every Send, no click needed, without forcing every node's state to reset (which would also wipe out running feedback buffers you didn't touch).

3. Pattern.set() (Pattern-specific)

For a Pattern held in persistent state specifically, there's a cheaper fix than either of the above — see Pattern.

Rendering primitives

GLSL

const glsl = use(GLSL, { width: 512, height: 512, filter: 'linear' });
glsl.tick(fragSrc, { uSrc: inputs.src, uSomeNumber: 1.0 });
return { screen: glsl };

Pass the fragment shader source (a #version 300 es string) into tick() every frame, not just once — it only actually recompiles when the string changed, so this is cheap, and it's what makes editing the shader text in your node's code() take effect live. Uniform values can be: anything with a .texture property (bound as a sampler2D), a number, a boolean (sent as 0.0/1.0), or a 2/3/4-length array (uniform2fv/3fv/4fv).

Every compiled shader gets vUv (0..1 across the frame, v=1 is visual top) as its varying, and can declare uniform vec2 uTexel to get 1 texel of uSrc in uv units (for neighbor-sampling effects like blur) — it's injected automatically for every GLSL-backed effect, ignored if your shader doesn't declare it.

WebGL feedback-loop rule: a shader can never sample the exact same texture it's currently rendering into — GLSL.tick() throws explicitly if you try (rather than silently freezing, which is what raw WebGL does). Route self-referencing feedback through Lag or Delay instead, which always copy into their own separate texture first.

Canvas2D

const canvas = use(Canvas2D, width, height, 'linear');  // filter: 'linear' | 'nearest'
const { ctx } = canvas;
ctx.clearRect(0, 0, width, height);
// normal ctx.* drawing calls
canvas.upload();  // call once you're done drawing this tick
return { screen: canvas };

Plain 2D canvas drawing, no GLSL involved — proves a "video-type" node doesn't need one.

Html

const html = use(Html, width, height);
html.tick(`<div style='color:white;font:32px sans-serif'>hello</div>`);
return { screen: html };

Rasterizes real HTML/CSS to a texture (via an SVG <foreignObject>), for richer text layout than ctx.font allows. Real limits: no cross-origin images or @font-face fonts inside the HTML (canvas tainting), and the texture updates one tick after the HTML string changes (rasterizing is asynchronous), not the same tick.

render() & preview()

render(value);  // puts `value` on the visible canvas THIS tick

The only thing that actually draws to screen. One shared instance for the whole graph — whichever node calls render() last in cook order wins for that tick. To change what's shown, move (or add/remove) the call, no in rewiring needed. 

preview(value, options?);

Opts this node into a floating preview card next to its own line, for this tick only — a node that never calls preview() gets no card and costs no extra per-tick texture readback. Call it more than once in one node's code() and each call gets its own card (stacked below the first), keyed by call order — same convention particle2d()/ ascii2d() use internally.

  • A texture-bearing value shows as an image.
  • A plain number is rounded to 6 decimals for display (so 0.1+0.2 shows 0.3, not 0.30000000000000004) — only the display is rounded, not the real value.
  • A bare Pattern auto-plots as a line graph (see Pattern) — default x-range is [0, 1]; override with preview(pattern, { range: [a, b] }).
  • Anything else is shown via JSON.stringify.

Effects (FX)

Every effect below is a class, constructed via use(EffectName, filter?) and called as .tick(src, ...args) — tick()'s return value is the actual texture, not the wrapper itself: 

const use = useInstances(state);
const out = use(Rotate).tick(inputs.src, t * 20);  // out has .texture, the Rotate wrapper doesn't
return { screen: out };                       // NOT { screen: use(Rotate) }

Every effect's constructor takes an optional filter argument (use(Translate, 'nearest')) — see Texture filtering.

Coming from Hydra? Modulate/Displace/ModulateScale/ ModulateRotate are straight ports of Hydra's own modulate/modulate-family functions, same formulas — the second argument is any texture-bearing value (another effect's output, a Noise, a whole other node's screen), not a plain number. 
// a circle's edge, pushed into an organic wobble by a noise field
const use = useInstances(state);
const map = use(Noise).tick({ scale: 4, seed: 1 });
const scaled = use(ModulateScale).tick(inputs.src, map, 0.8, 1);
const out = use(ModulateRotate).tick(scaled, map, 2, 0);

All four take a trailing fill argument (default 'clamp') controlling what happens where the modulation pushes the sample coordinate outside 0..1:

fillLook
'clamp'Default. Repeats the nearest edge pixel outward — smooth, but can smear if that edge is a hard color boundary.
'transparent'0 alpha outside 0..1 instead — no smear, a clean cutoff. Same convention Rotate/Scale already use.
'wrap'Tiles the source. Real Hydra never sets an explicit texture wrap mode, so it inherits WebGL's own REPEAT default — this is what gives a large modulateScale amount that "folds into a 3D plane" look some Hydra patches have. Try it at extreme multiple values for the same effect here.
const out = use(ModulateScale).tick(inputs.src, map, -1.4, 1, 'wrap');  // the Hydra "3D plane" look

Warp / Ripple

Unlike the single-shader effects above, these two take an ARRAY of points and build their shader fresh only when the point COUNT changes — each point contributes its own localized distortion, and overlapping points compose rather than one replacing another. 

const out = use(Warp).tick(inputs.src, [
  { x: 0.5, y: 0.5, radius: 0.4, amount: 0.8 },
]);

A localized bulge/pinch per point, not a full-frame distortion. x/y: 0..1 uv space. radius (default 0.3): how far it reaches before fading out. amount (default 0.5): positive magnifies outward (a lens held over that point), negative pinches inward. 

const out = use(Ripple).tick(inputs.src, [
  { x: 0.3, y: 0.5, frequency: 40, amplitude: 0.02, speed: 4 },
  { x: 0.7, y: 0.5, frequency: 20, amplitude: 0.03, speed: 2 },
], t);

Each point radiates its own outward-moving wave; where two points' waves reach the same pixel they blend (inverse-square-distance weighted) rather than one replacing the other — right next to a point its own wave dominates, roughly equidistant between two is where you see a genuine blend. frequency (default 40): ripples per unit distance, higher = tighter rings. amplitude (default 0.02): how far pixels get pushed. speed (default 4): how fast the rings travel outward. Needs t — the third argument — for the rings to actually animate.

Compositing: Composite / Matte / Layer

const out = use(Composite).tick(a, b, mode, opacity);

Layers b onto a. mode: Porter-Duff ('over' default, 'atop', 'xor') or a color blend ('multiply', 'screen', 'darken', 'lighten', 'add', 'difference', 'hardLight', 'softLight', 'lightest', 'darkest'). opacity (0..1, default 1) fades b before compositing.

Never wire b to this same node's own output directly — reading a texture while it's the active render target throws. Route the fed-back side through Lag or Delay first. 
const out = use(Matte).tick(a, b, matteSource);

Mixes a/b per-pixel using a third source's own luminance as the mix factor (0 = all a, 1 = all b) — a luma matte/mask. 

const out = use(Layer).tick([layerA, layerB, layerC], 'over', 1);

Reduces a whole ARRAY of texture-bearing values down to one by repeatedly compositing each on top of the previous — textures[0] on the bottom, the last entry on top. Just Composite driven in a loop (any of its modes work here too) — for when the number of layers is itself dynamic, instead of a fixed handful of separate use(Composite) calls chained by hand.

ComposeAt (picture-in-picture)

const out = use(ComposeAt).tick([
  { value: inputs.a, x: 0,   y: 0,   w: 0.5, h: 0.5 },
  { value: inputs.b, x: 0.5, y: 0,   w: 0.5, h: 0.5 },
  { value: inputs.c, x: 0,   y: 0.5, w: 1.0, h: 0.5 },
]);

Composites each rect's own texture into its own rectangle of the frame — a lightweight multi-viewport/picture-in-picture layout tool, built fresh only when the rect COUNT changes (same pattern as Warp/Ripple above). x/y are each rect's TOP-LEFT corner (0..1, y=0 at the top — matching how you'd place it on screen); w/h are its size (0..1). Rects draw in array order, so a later entry overlaps an earlier one where they intersect. A rect with a missing/unwired value doesn't throw, but won't reliably stay blank either — wire every rect's input if you don't want stale content showing through.

Type $compose_at(n)$ in the editor for a click-to-place UI that generates a node's rects for you, rather than hand-typing coordinates.

Feedback: Lag / Delay

const held = use(Lag, every, filter).tick(value, every);

Holds a value and only refreshes it once every every calls — a frequency divider (step-holds between updates, never shows intermediate frames). Safe to hold a texture-bearing value: Lag snapshots it into its own texture at the moment it fires, rather than just keeping a reference (which would just keep showing whatever the upstream node draws this frame, live). 

const out = use(Delay, ticks, filter).tick(value, ticks);

Shows exactly what value was ticks ticks ago — a true sliding delay line, continuously shifting by one frame every tick (unlike Lag, which steps). Costs ticks + 1 separate GPU textures internally (a ring buffer).

Both exist specifically so a node can safely read its own recent history — the thing that makes feedback loops (trails, video-synth-style zoom/spiral effects) possible without ever violating the "can't sample your own active render target" rule.

Texture filtering (NEAREST)

Every texture-owning class (GLSL, Canvas2D, every effect, Lag, Delay) takes an optional filter argument: 'linear' (default, smooth) or 'nearest' (blocky, no interpolation).

Why this exists: in a feedback loop, something like Translate/Scale/Rotate resamples its input at a fractional/scaled uv coordinate every single tick. With the default LINEAR filtering, each resample blends neighboring texels a little — harmless once, but it compounds: after enough iterations through the loop the image gets visibly, progressively blurrier. This is not compression — nothing in this pipeline compresses anything — it's cumulative bilinear resampling, the same reason old analog video-feedback effects look the way they do.

'nearest' on the texture that gets fed back through the loop (typically the Delay/Lag and whatever effects read it) stops that specific compounding, at the cost of visible pixel-stepping/aliasing instead of smoothness: 

let out = use(Delay, undefined, 'nearest').tick(inputs.src, ticks);
out = use(Translate, 'nearest').tick(out, { x: 0.01, y: 0.01 });
out = use(Scale, 'nearest').tick(out, { x: 1.01, y: 1.0 });

The default project's own feedback loop uses exactly this — flip any of those back to omit the argument (or pass 'linear') to compare.

Generators: Ramp / Gradient / Noise / Colors / Colormap

Generators don't take a src — they draw their own content from scratch every tick.

const out = use(Ramp, width, height).tick({ angle: 0, from: [0,0,0], to: [1,1,1] });

A 2-color gradient. angle in degrees (0 = left-to-right), from/to are [r,g,b] in 0..1.

const out = use(Gradient, width, height).tick([COLORS.RED, '#00ff00', COLORS.BLUE], [0, 0.3, 1]);

A multi-stop gradient — any number of colors (hex string, COLORS.X, or [r,g,b] 0..1 array), using the browser's own real gradient interpolation (drawn via Canvas2D, not reimplemented in GLSL). stops (the second array, 0..1, same length as colors) is optional — omit it and colors space evenly. Only actually redraws when colors/stops CHANGE from the last tick, so it's safe to call every tick with live values (a colorPicker(), say) without a newPatch guard. This is the "hand-drawn ramp" half of the Ramp → GradientMap palette-mapping trick (see the Effects table above) — build an arbitrary-stop gradient here, then GradientMap.tick(src, thisGradient) repaints src entirely from it. 

const out = use(Noise, width, height).tick({ scale: 4, seed: 0, z: t, octaves: 4, type: 'value', mono: true });

type: 'value'/'perlin' (smooth/cloudy — perlin is genuine gradient noise, smoother and more directional than value noise), 'voronoi' (Worley/cellular distance field), or 'static' (flickering TV noise, no smoothing at all). Genuinely 3D — animate z (not seed) to morph the field in place with no x/y panning; seed is just a fixed per-instance offset. octaves only matters for 'value'/'perlin' (capped at 8). mono: false gives a decorrelated-per-channel color version instead of grayscale. 

COLORS.RED / ORANGE / YELLOW / GREEN / CYAN / BLUE / PURPLE / PINK / WHITE / BLACK

Plain hex string constants — not a function call, just handy names for anywhere a project wants a color (Colorize.tick(src, COLORS.RED), ChromaKey.tick(src, COLORS.BLACK), a Gradient stop, a Canvas2D ctx.fillStyle). Every color argument in this project accepts a bare hex string just as well — these just save typing/typos for the common ones. 

const out = COLORMAPS.viridis;  // NOT a function call - already a texture, built once and cached

COLORMAPS.viridis / plasma / inferno / magma / cividis / turbo / jet / rainbow / coolwarm / spectral / ... — each a ready-made gradient texture, no use()/tick() needed. tab10/tab20 are the exception: plain hex arrays to index (COLORMAPS.tab10[i % 10]), not a gradient. To scroll one, run it through Translate's wrap option: 

const out = use(Translate).tick(COLORMAPS.viridis, { x: t * 0.1, wrap: true });

Most colormaps aren't cyclic (viridis's first stop is dark purple, its last is yellow), so scrolling one this way shows a visible seam where it wraps. COLORMAPS.loop.viridis is a palindrome version of the same stops (forward then backward) - same cost, genuinely seamless to scroll: 

const out = use(Translate).tick(COLORMAPS.loop.viridis, { x: t * 0.1, wrap: true });

Every colormap also has .read(t) — a CPU-side lookup (t: 0..1) returning the color at that point as a plain [r,g,b] 0..1 array, read straight off the same canvas the texture itself was drawn from. For whenever you want the colormap's color driving something other than a texture — feeding Colorize, a Canvas2D fillStyle, a per-instance color in an Instance/particle2d callback: 

const out = use(Colorize).tick(src, COLORMAPS.viridis.read(x));  // x: 0..1

Every colormap

The actual stops, rendered — not a stand-in, these are the same hex values GRADIENT_STOPS in lib/colormaps.js builds each texture from. tab10/tab20 are drawn as discrete swatches instead of a smooth bar, since — unlike every other name here — they're plain hex arrays to index, not a gradient: there's no in-between color to show, just those N flat, unordered ones.

Bloom / Flow

Not generators — they take a src and brighten/glow its highlights.

const out = use(Bloom).tick(src, { threshold: 0.6, blurAmount: 3, intensity: 1 });

Genuinely a 3-pass effect (bright-pass extract → blur → additive combine), so it's a hand-written class rather than a single-shader FX entry. 

const out = use(Flow).tick(src, {
  threshold: 0.6, softness: 0.2, wideBaseRadius: 4, wideGain: 1.5,
  wobbleAmount: 0.015, wobbleSpeed: 0.15, feedback: 0.85,
  tightBaseRadius: 1, tightGain: 2, t,
});

A heavier, full-detail glow — a multi-level weighted blur pyramid plus noise-driven wobble plus its own internal feedback loop, roughly 30 draw calls a tick (needs t for the wobble to animate). Reach for Bloom first (same 4-layer composite idea, one blur pass per direction, no wobble/ feedback, a fraction of the cost) and only reach for Flow when the liquid/plasma wobble is specifically the look you're after and can afford it.

Melt

Fake pixel sorting — real pixel sorting (sorting each row/column's own pixels by brightness, fresh, every frame) is genuinely expensive and awkward on a GPU. This fakes the same "melting" look for a fraction of the cost: pick one row or column, and feed it back into itself every tick, sliding a little further away and fading a little more each time. There's no actual sorting happening — the trail is really just last tick's trail, shifted and dimmed. 

const out = use(Melt).tick(src, {
  axis: 'y', line: 0.5, thickness: 0.004, drip: 0.01, dieOff: 0.95,
});
OptionMeaning
axis'y' (default) picks a horizontal line — melts downward. 'x' picks a vertical line instead.
line0..1 position of that line along its axis. Animate it yourself (0.5 + Math.sin(t) * 0.3) for a source that wanders instead of sitting still — the trail keeps dripping from wherever the line currently is.
thicknessHalf-width (uv units) of the source strip. Keep this near one texel for a clean "single row" look — wider reads more like a soft band.
dripHow far (uv units) the trail slides away from the line each tick — higher drips faster.
dieOffPer-tick brightness/alpha multiplier on the trail — 1 keeps it forever, lower fades it out faster. With a perfectly static source this converges to a fixed decaying gradient rather than growing forever.
The side of the line that ISN'T dripping stays untouched, plain live src — this only ever replaces content on the "away" side, it never blends with or darkens the rest of the frame.

Fill

Fills src's transparent areas — cuts the frame into rows, finds where each row's own real content starts/ends (via alpha), and extends that same row sideways to cover the rest of it. A row with nothing of its own borrows the nearest row that has something, so the whole frame ends up covered even when the real content only occupies a small part of it. 

const out = use(Fill).tick(inputs.webcam, 'mirror');
modeWhat it does
'mirror' (default)Extends each row by reflecting it back on itself — no seam at the fold.
'copy'Extends each row by repeating it, wallpaper-style.

Pattern

A Pattern wraps a plain x => number function — a math-function object you can read, transform, chain, and plot. JavaScript has no operator overloading, so pattern * 2 can never return a new Pattern (it just coerces to NaN) — the methods below are the real equivalent. 

const pat = new Pattern(x => x * 2);   // cheap - just a function, build one fresh anytime
pat.read(3);                        // -> 6

Static shape constructors

Each already outputs 0..1. freq/phase scale/shift x before the shape is applied.

CallShape
Pattern.sin(freq, phase)Sine, remapped to 0..1.
Pattern.ramp(freq, phase)Sawtooth, 0 → 1 then jumps back to 0.
Pattern.square(freq, phase)1 for the first half of each cycle, 0 for the second (fixed 50% duty cycle).
Pattern.triangle(freq, phase)Linear up then linear down.
Pattern.random(freq, phase)A new random value (0..1) each integer step of x*freq — a stepped hold, not smooth noise.
Pattern.pulse(freq, width, phase)Like square, but with a controllable duty cycle — width (default 0.1) is the fraction of each cycle that reads 1. pulse(freq, 1) ≡ square(freq).
Pattern.sequence(values, mode, freq, phase)Cycles through a plain array. mode: 'step' (default, jumps) or 'smooth' (interpolates toward the next value, wrapping last → first). Hydra's [0,1].smooth() array trick, without monkey-patching Array.prototype.
Pattern.sequence([0, 1], 'smooth').read(t);   // breathes 0 -> 1 -> 0, once per second
Pattern.sequence([1, 4, 2, 8], 'step', 2).read(t);  // holds each value 1/8s, two passes/sec

CallWhat it does
pat.read(x)The value at one x.
pat.get(start, end, step=1)A whole range at once — end exclusive, like a for-loop. For instancing: pat.get(0, count) hands back exactly count values.

Chaining (each returns a NEW Pattern)

CallWhat it does

set() — the one mutating method

lfo.set(fn);          // swaps THIS instance's wrapped function in place
lfo.set(Pattern.ramp(1, t % 100));  // a truly dynamic pattern: call .set() every tick

Every other method returns a NEW Pattern — .set() mutates the same one instead. That distinction is the fix for the state-persistence gotcha above: reassigning state.lfo = new Pattern(...) on a later patch send loses whatever's cached ON that instance (.plot()'s own canvas) and starts over; state.lfo.set(...) keeps the same instance (and its cache) while still changing what it computes. It's also what makes a genuinely time-varying pattern possible — call .set() every tick with fresh values baked in, since the static factories themselves (Pattern.ramp(freq, phase)) only bake in whatever freq/phase were at the moment they were called: 

const use = useInstances(state);
const lfo = use(Pattern).set(Pattern.sin(0.3));  // re-applied every tick - editing the
                                          // shape here takes effect on next Send

plot() — for preview()

pat.plot({ width: 256, height: 64, range: [0, 1], samples: 128, color: 'rgb(140,217,140)' });

Draws this pattern as a line graph (a Canvas2D drawing — the wrapped function is arbitrary JS, it can't run on the GPU) and returns the texture. Caches its own canvas on this, so reuse the same Pattern instance (via useInstances) for that cache to actually help. Shows axis labels: top-left 1, bottom-left 0 and the range start, bottom-right the range end — the y-axis is always this fixed 0..1 scale regardless of what the wrapped function actually returns (values outside 0..1 plot off the top/bottom edge, unclamped).

A bare Pattern passed to preview() auto-plots — see render() & preview().

Scope

const use = useInstances(state);
const scope = use(Scope, 128);  // ring-buffer length, in samples
const trace = scope.tick(someLiveValue, { width: 512, height: 192, color: 'rgb(140,217,140)' });
preview(trace);  // or return { screen: trace }

Unlike Pattern.plot() (which plots a mathematical function over a domain — stateless, nothing to do with time passing), Scope keeps its OWN rolling history of whatever value you feed it each tick and draws that scrolling by, like a real oscilloscope — newest sample at the right edge, oldest drops off once the buffer fills. Same visual conventions as Pattern.plot() (auto-scaled y-axis unless you pass a fixed range: [min, max], a zero-crossing reference line, labeled min/max) so the two read as one family. Good for watching a raw exported number you don't already know the range of — midiKnob(), an AudioSource band, a physics body's velocity.

Instancing & particles

Stamps many positioned/scaled/rotated copies of ONE source texture into a single shared destination — real WebGL2 GPU instancing (drawArraysInstanced + per-instance vertex attributes), so it's always exactly ONE draw call and ONE destination texture, no matter how large count is.

particle2d — the batteries-included entry point

const out = particle2d(source, cols, rows, stamp, {
  t, min: 0.15, shakeSpeed: 0, shakeAmount: 0.006, channel: 'lightness',
});

Samples source down to a cols × rows grid and stamps one copy of stamp (e.g. dot()/pixel(), see below) per cell, sized by that cell's brightness — no callback needed, and no useInstances()/use() boilerplate: call it directly from code(). It gets its own persistent identity from the same "current node + call order" trick preview() uses, so calling it twice in one node gives two independent systems.

OptionMeaning
tCurrent time — only needed if shakeSpeed > 0. Default 0.
minFloor for a cell's size, as a fraction of 1/cols — a fully dark cell still draws at this size. Default 0.15. Formula: scale = (1/cols) * (min + v*0.85).
shakeSpeed0 (default) = perfectly static grid. >0 adds per-cell time-based position jitter at that speed.
shakeAmountJitter magnitude, uv units. Default 0.006.
channel'lightness' (default), 'red', 'green', 'blue' — which of sampleTexture's channels drives size/opacity.

dot() / pixel() — stamp shapes

dot(size = 64);    // cached white circle, transparent bg
pixel(size = 64);  // cached white square, transparent bg

Both are shared/cached by size across the whole project (read-only content, safe to share) — use as particle2d's stamp argument.

ascii2d — a text-grid renderer

const out = ascii2d(source, cols, rows, { channel: 'lightness', ramp: ' .:-=+*#%@', color: 'white' });

Like particle2d, but draws a character per cell instead of a stamped texture, and never shakes (a text grid doesn't read as "alive" the way a wobbling dot does — it just reads as blurry). Picks a character from ramp by value: low value → the start of the ramp (space = nothing drawn), high value → the end ('@' by default). White text on transparent background.

Instance — the raw primitive

const use = useInstances(state);
const out = use(Instance).tick(source, count, (i, count) => ({
  x, y, scale, rotation, opacity,
}));

What particle2d is built on — use this directly when you need custom per-instance placement (a Pattern-driven layout, say) rather than "a grid sized by brightness."

Callback fieldMeaning
x, y0..1 center, same uv space as every effect. Default 0.5, 0.5.
scaleFraction of the full frame (1.0 = fills it, matches Scale's convention). Number for both axes, or {x,y}/scaleX/scaleY independently. Default 1.
rotationDegrees. Default 0.
opacity0..1. Default 1.

Cleared to fully transparent at the start of every tick and composited with standard alpha-over blending — gaps between instances, and anything beyond count, stay transparent rather than turning black.

sampleTexture

const values = sampleTexture(value, { cols: 8, rows: 8, channel: 'lightness' });
// -> flat array (0..1), row-major, index = row*cols+col, row 0 = visual top

Reads a texture down to a coarse grid and returns one number per cell. channel: 'lightness' (default, standard luminance-weighted average) or a single raw channel: 'red'/'green'/'blue'.

This is a real GPU→CPU readback (gl.readPixels) — genuinely not free, which is why it downsamples to a coarse grid first (one small GPU render pass lets the GPU's own bilinear filtering do the averaging, then exactly ONE readPixels call reads the whole small buffer) rather than reading every pixel or making cols*rows separate readback calls.

slider / button / input / colorPicker

slider('freq', { min: 0, max: 1, step: 0.01, default: 0.5 });  // -> current numeric value
button('go', { default: false });                             // -> current boolean value
input('label', { default: 0, type: 'number' });                  // -> current value

Each call renders a floating widget next to the line it's declared on and returns its current live value — dragging the slider (or clicking the button, typing into the input, or picking a color) updates what the NEXT call to that same name returns. Values are keyed by name and held OUTSIDE any node's state, so they survive patch sends untouched (editing unrelated code doesn't reset a slider back to its default — only a real page reload does). Type $slider$, $button$, $input$, or $color_picker$ in the editor for an auto-numbered starter snippet.

colorPicker()'s return value is a plain hex string — feed it straight into anything that takes a color: Colorize.tick(src, tint), a Gradient stop, ChromaKey's key color.

Renaming a slider/button/input/ colorPicker call's NAME (not moving it) reuses that same widget row rather than creating a new one — this is handled correctly (the label and value both retarget to the new name immediately), but the OLD name's value stays parked at whatever it was, orphaned, since nothing reads it anymore.

nodeFunction

state.rotateThenShrink ??= nodeFunction((use, src, degrees) => {
  let out = use(Rotate).tick(src, degrees);
  out = use(Scale).tick(out, 0.9);
  return out;
});
const out = state.rotateThenShrink(inputs.src, t * 20);

Packages a composed pipeline of effects into a single reusable callable. Unlike a node's own code(), which gets use from ITS OWN state, the function this returns carries its OWN independent, persistent state internally — built once, when nodeFunction(...) itself is called — so the effects it constructs stay correctly cached no matter which node ends up calling the returned function, or how many times. Build it once (state.x ??= nodeFunction(...), or once at module scope to share across every node in the file) and reuse the returned function. Anything that changes tick to tick has to be an argument to the RETURNED function's call, not read from outside — the builder callback only ever runs once.

Tempo: beatmatch / beatEnvelope

const { beat, phase, pulse, value } = beatmatch(120, t);
const out = use(Rotate).tick(inputs.src, 20 * value);

Given a tempo (bpm) and the project clock's elapsed seconds, returns which beat "now" falls on and how far through it we are — properly timed off a real bpm number instead of a hand-tuned Math.round(t / someSecondsPerBeat).

FieldMeaning
beatInteger count of whole beats since t=0 — increments exactly on the beat.
phase0..1 progress through the current beat (0 = right on the beat) — for smooth per-beat interpolation instead of a hard step.
pulsetrue for the brief window (pulseWidth, default 0.08) right around the beat — handy for triggering a hit once per beat.
valuephase reshaped by shape (see beatEnvelope below) — usually what you actually want driving brightness/scale/etc, not the raw linear phase.
step, stepPhase, stepPulse, stepValueSame four ideas as beat/phase/pulse/value, but at subdivide steps per beat (default 1 — a step IS a beat) — pass { subdivide: 4 } for a trigger every quarter-beat, 3 for triplets, etc. stepValue is stepPhase reshaped by the same shape, so e.g. subdivide: 4 with shape: 'pulse' gives 4 quick spikes per beat instead of 1.
const { step, stepPulse, stepValue } = beatmatch(120, t, { subdivide: 4, shape: 'pulse' });
out = use(Brightness).tick(out, stepValue);  // 4 quick flashes per beat
beatEnvelope(phase, 'triangle', { peak: 0.5 });  // -> 0..1, reshaped

Reshapes a 0..1 phase (from beatmatch above, or any other 0..1 progress value, e.g. a Pattern) into one of several named envelope curves — standalone/exported separately so it's usable against a phase from anywhere.

ShapeCurve
'pulse'Quick spike right on the beat, fast exponential decay (decay, default 12).
'build'Smooth (sine-shaped) symmetric build-and-fall.
'triangle'The default. Same build-and-fall, but a straight-line ramp — peak (0..1, default 0.5) moves the corner.
'adsr'Full attack/decay/sustain/release envelope — each phase's length as a fraction of the beat (attack/decay/sustain/release, must sum to ≤ 1; leftover holds at sustainLevel).
'sawJump'Ramps -1..1 across the beat, then jumps back to -1.
'inverse'1/x-style falloff — spikes at the beat, falls off fast (falloff, default 8).

MIDI: midi / midiKnob / midiPad / LPD8

Reading midi.knobs/midi.pads (or calling midiKnob()/midiPad()) triggers a lazy connect — the browser's own Web MIDI permission prompt, same convention as WebcamSource/AudioSource. Check midiError() if it was denied or isn't supported (Safari doesn't implement Web MIDI as of this writing; Chrome/Edge are the safe choice). 

preview(midi.knobs);  // { knob_20: 0.5, knob_21: 0.12, ... } - grows as you touch each control
preview(midi.pads);   // { pad_60: true, pad_62: false, ... }

midi.knobs/midi.pads are plain key-value stores that grow automatically the moment a new CC/note number is actually seen, keyed by a readable "knob_N"/"pad_N" string — no hardcoded per-device mapping needed, since different controllers (even the same model's mk1 vs mk2) send wildly different numbers. Every new CC/note is also logged to the console (prefixed [midi]) the first time it's seen, so you can watch which physical knob/pad maps to which number as you touch each one. Type $midi$ in the editor for a ready-made "watch everything" starter node.

Once you know the number you want, the direct-read helpers are usually nicer than indexing the store yourself:

CallWhat it does
midiKnob(cc, {min,max,default})Last CC value, scaled to [min,max]. Unknown/untouched CC → default (which defaults to min) rather than silently reading 0.
midiPad(note, {mode})mode: 'momentary' (default) → true while held. 'toggle' → flips once per press, like button().
midiVelocity(note)0..1 from the most recent press — holds its last value after release rather than resetting to 0.

const pressed = midiPad(60, { mode: 'toggle' });

LPD8/LPD8_MK2 are ready-made factory CC/note mappings for the Akai LPD8 (the mk2 ships DIFFERENT numbers than the original — knobs on CC 20..27, pads on a C-major scale rather than chromatic):

const hit = midiPad(LPD8_MK2.padsA[0]);

Image / Video / Webcam

const img = use(ImageSource, width, height);
img.tick(url, { fit: 'contain' });  // fit: 'contain' (default) | 'cover' | 'stretch'

Loads a photo or animated GIF (the browser advances a loaded GIF's frame on its own — redrawing it every tick is all animation needs). source is a plain URL string, or a File/Blob from files.get('name.jpg') (see below). width/height are a CAP, not a target — the working buffer shrinks to the image's real native size if smaller, so there's no wasted redraw/upload cost.

fit: 'contain' (letterboxed, aspect preserved — right for anything meant to be looked at), 'cover' (crops to fill, preserves aspect), 'stretch' (fills exactly, distorts aspect — right for texture DATA where every pixel's normalized position matters more than visual distortion, e.g. a color-lookup LUT strip). 

const video = use(VideoSource, width, height);
video.tick(url, { fit: 'contain', start: 0, end: 100, speed: 1, reverse: false });

Plays and loops a video (muted + playsInline, so autoplay works without a user gesture in most browsers).

speed sets video.playbackRate (0.5 = half speed, 2 = double). reverse: true plays the trimmed [start,end] window backward — browsers don't reliably support a negative playbackRate, so this pauses the element and steps currentTime backward by hand each tick instead, based on real elapsed time (speed still applies as the backward rate). 

video.jumpToRandom(start = 0, end = 100);  // seeks to a new random point in that window

Call this yourself whenever you want a cut — a button() press, a keyPulse(), a beat pulse from beatmatch — it doesn't happen automatically on its own each tick. 

const cam = use(WebcamSource, width, height);

Runs Hydra DSL code in its own separate WebGL context (never added to the page), copied into this project's texture pipeline. Only re-evaluates when the code string actually changes, so editing it in your node's code() takes effect live without losing Hydra's own internal state every tick.

Extrude

const extrude = use(Extrude);
const mesh = extrude.tick(shape, { depth: 0.3, resolution: 32, threshold: 20 });
if (!state.added) { state.scene.add(mesh); state.added = true; }

Turns a flat 2D shape into a real, lit, rotatable 3D one. shape is any texture-bearing value (a Canvas2D drawing, inputs.src, a ChromaKey'd chop, anything with a shape in its alpha) — tick() reads its alpha channel on a coarse resolution×resolution grid and builds one small box per covered cell, extruded along Z by depth and colored from that cell's own RGB. It's a "voxel-relief" look, not a smooth silhouette extrusion — real contour tracing would be far more expensive to redo every tick, and the blocky look fits a livecode-visuals context fine.

Returns a THREE.Mesh owned by the Extrude instance — its geometry is rebuilt in place every tick, but it's the same mesh object each time, so add it to your scene once (same if (!state.added) guard as ModelSource above), then rotate/light/orbit it like any other mesh.

Cost is one CPU texture readback per tick at resolution² pixels — the same order of cost as three.toTexture()'s own readback. Keep resolution modest (24–48) for anything ticking every frame; higher looks smoother but costs more CPU per tick. Try $extrude$ (feed it $star$ or any other alpha-bearing source) for a working starting point.

Physics (matter-js)

ball: {
  in: {},
  code(inputs, state, t) {
    const gravity = 1;
    const bounciness = 1.1; // > 1 gains energy each bounce instead of settling
    const spawnEvery = 1; // seconds
    const { width, height } = screenSize();
    const use = useInstances(state);
    const canvas = use(Canvas2D);
    const { ctx } = canvas;

    if (!state.world) {
      state.world = new PhysicsWorld({ gravity });
      state.platformId = state.world.addPlatform({ x: width / 2, y: height * 0.7, width: width * 0.6, angle: 45, restitution: bounciness });
      state.lastSpawn = -spawnEvery;
    }
    // static bodies don't rotate on their own - set the angle yourself
    // every tick if you want it moving (here, oscillating +/- 20deg).
    state.world.setAngle(state.platformId, 45 + Math.sin(t) * 20);
    if (t - state.lastSpawn >= spawnEvery) {
      state.world.addBall({ x: width / 2, y: 0, radius: 20 });
      state.lastSpawn = t;
    }
    state.world.tick();

    ctx.fillStyle = '#000';
    ctx.fillRect(0, 0, width, height);
    for (const body of state.world.all()) {
      ctx.save();
      ctx.translate(body.x, body.y);
      ctx.rotate((body.angle * Math.PI) / 180);
      ctx.fillStyle = body.kind === 'ball' ? '#4ae' : '#888';
      if (body.kind === 'ball') {
        ctx.beginPath();
        ctx.arc(0, 0, body.radius, 0, Math.PI * 2);
        ctx.fill();
      } else {
        ctx.fillRect(-body.width / 2, -body.height / 2, body.width, body.height);
      }
      ctx.restore();
    }
    canvas.upload();
    return { screen: canvas };
  },
},

PhysicsWorld wraps matter-js, a real 2D physics engine — gravity, collision, and restitution/bounciness are all handled for you. It only simulates; it doesn't render anything itself, so pull body positions back out with world.all() (or world.get(id)) and draw them yourself, same "just simulation, you draw it however you like" split as everything else here — Canvas2D above, or feed positions into GLSL/Instance instead if you'd rather.

world.addBall({ x, y, radius, restitution, friction }) and world.addPlatform({ x, y, width, height, angle, restitution }) (the latter isStatic — it never falls, but still collides) both return an id for world.get(id) / world.remove(id) later. Positions are plain pixels (matching screenSize()), not the 0..1 uv space Warp/Ripple/Instance use elsewhere — divide by width/height yourself if you need 0..1. angle is in degrees, matching Rotate's own convention. matter-js uses the higher of the two colliding bodies' own restitution, so a bouncy platform alone is enough to make any ball bounce hard off it — values above 1 gain energy each bounce instead of settling.

Call world.tick() once per code() call to advance the simulation — this project drives the clock itself rather than letting matter-js run its own internal loop, same convention as ThreeSource/HydraSource.

A static body (like the platform above) never moves from physics alone — call world.setAngle(id, degrees) every tick if you want it rotating (a moving platform, a spinning obstacle); the example above oscillates it with Math.sin(t). Bodies still collide correctly wherever they currently are, so a ball mid- flight will bounce off the platform's up-to-date angle.

Editor shortcuts

$name$ — a node template's bare body

Type someKey: $glsl$ (or $canvas$, $node$, $square$, $particle2d$, $three$, ... — any node-template name) and finish the closing $: it expands in place into that template's { ... } body, using the key you already typed rather than a generated placeholder one.

$explode(name)$ — full source, generated key

Type $explode(rotate)$ and finish the closing )$: for an effect name, this inserts that effect's exact raw GLSL shader source — useful for dropping into a plain GLSL node body and hand-editing from a known-working version. For a node-template name, it inserts a complete standalone newXNode: { ... }, entry with a generated key, ready to paste in and rename. $ is deliberate: the pattern requires the literal text explode( and )$, so a JS template-literal interpolation like ${'{'}uTime{'}'} elsewhere in a node's code has a different shape and can't be mistaken for it.

Same idea also covers $load$/$downscale$ (file pickers, see Media) and $slider$/ $button$/$input$ (control snippets, see Controls).

explode('name') is also callable directly (e.g. from the browser console) to just print the text instead of inserting it.

Per-node reset button

Every node gets a small ↺ button in the editor's left margin, next to its opening line. Clicking it clears that node's state to {} — every if (!state.x) guard (and every use() call) fires fresh again on the very next tick, no resend needed. This is the manual, no-code-change alternative to newPatch for the same "one-time-setup" gotcha — reach for the button when you just want to force ONE node fresh right now; reach for newPatch when you want a node to rebuild on every future Send automatically.

Gotchas & FAQ

Nothing shows up on screen

Returning {screen: x} from a node doesn't draw anything by itself — check that some node in the chain actually calls render(x) (or something derived from x).

My input reads as undefined

Check the exact port name — in: { src: 'foo.output' } only works if foo's code() literally returns { output: ... }. There's no special meaning to any particular key name; it has to match exactly.

Editing inside a "build once" block does nothing

See State, useInstances, newPatch — this is the #1 surprise in this project's whole model.

"Reading a texture while it's the active render target" error

You wired a node's own output back into itself (directly, or into Composite's two inputs where one traces back to the node's own result) without routing it through Lag or Delay first. Both always copy into their own separate texture, which is what makes reading "your own recent past" legal on the GPU.

A feedback loop keeps getting blurrier

See Texture filtering (NEAREST) — not a bug, cumulative bilinear resampling.

A circle/instance has a black background instead of transparent

Shouldn't happen with the built-in effects/instancing (every shader here preserves alpha correctly, and Instance/particle2d clear to fully transparent every tick with proper alpha-over blending) — if you see this with your own custom GLSL, check your fragment shader is actually writing a meaningful alpha channel (outColor = vec4(rgb, a)) rather than always 1.0.

Multiple useInstances()/use() calls acting weird

use() calls must run unconditionally, in the same order, every single tick — never inside an if. Putting one behind a condition shifts every LATER call in that same tick onto the wrong cached instance.
